# 0001. 规则执行采用「期望状态 → 差异 → 执行」模型

日期：2026-09-29　状态：已接受

## 背景

条件满足就执行动作（"事件 → 动作"直连）会带来重复执行：窗口每 resize 一次就 enable 一次插件；Toggle 类 Command 被反复触发造成状态震荡；多个事件并发时动作互相踩踏。用户需求明确要求避免这些。

## 决策

规则引擎不直接执行动作，而是：

1. 环境快照（EnvironmentState）+ 全部规则 → 计算**期望状态**（DesiredState，插件期望启停表）；
2. 与**实际状态**（`app.plugins.enabledPlugins`）做 diff；
3. 只对不一致项执行动作。

Command 类动作不是状态、无法 diff，采用边沿触发（见 ADR 0004）。

## 理由

- 重复 resize 时期望状态不变 → diff 为空 → 零动作，天然消除震荡与重复 API 调用。
- 多规则同目标冲突在"期望状态合并"阶段解决（按 priority 高者胜，平局取规则数组靠前者并在 Diagnostics 告警），而不是执行阶段抢跑。
- 只在不一致时才 enable/disable 插件，避免昂贵操作。

## 后果

- 好：执行幂等、可测试（纯函数：merge + diff 可单测）、无循环触发。
- 坏：Command 类动作无法纳入 diff，需要单独的边沿机制（ADR 0004）。
- 跟进：合并冲突的平局规则在 Diagnostics 显示 warning。
