# 0007. 受管插件状态以规则为准（手动更改会被再强制）+ 自保护

日期：2026-09-29　状态：已接受

## 背景

规则要求 Plugin A = ON，用户手动在社区插件页把 A 关掉。下一次环境 evaluate 时行为应该是什么？另外，用户规则可能误把 Adaptive Workspace 自己关掉，导致引擎失去控制权。

## 决策

1. **再强制**：受规则管理的插件，其状态以规则计算出的 DesiredState 为准。用户手动更改后，下一次 evaluate（含启动、环境变化、规则编辑、手动"立即评估"）会把状态改回规则要求值。该行为写入 README 与 Diagnostics（Managed Plugins 显示 current/desired/lastAction）。
2. **自保护**：任何 Action 的 target 为本插件自身（`adaptive-workspace`）时拒绝执行，记 error 日志，不中断其他动作。
3. **卸载残留披露**：启停采用 AndSave（ADR 0005），卸载本插件后插件状态停留在最后一次应用值；README 明确说明，Diagnostics 提供受管清单便于用户恢复。

## 理由

- 自动化的价值在于"期望状态总是成立"，容忍手动覆盖会让环境切换随机失效（用户核心诉求是"设置一次不用管"）。
- 自保护是安全边界：引擎不能自杀，否则用户在错误规则下可能失去恢复入口。

## 后果

- 好：行为可预测、可解释；Diagnostics 能直接回答"为什么我的开关自己弹回去了"。
- 坏：与"临时手动测试插件"的场景冲突（手动关掉会被弹回）——缓解：规则可临时停用（rule.enabled）或总开关关闭；Diagnostics 文案提示这一点。
- 跟进：无。
